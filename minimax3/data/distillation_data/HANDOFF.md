## 3. Why most subagents failed (read this before spawning more)

The dominant failure mode was: **subagent returns a planning message instead of tool
calls**. The closing message looks like "I'll start by reading the seed file…", "Good —
now I'll write a Python generator script to a temp file…", "Let me write each snippet
with proper escape handling…", etc. — but no files are written. The subagent treats
its return message as a status report and stops there.

**Variations of the failure:**
- Reads the references, says "I have the format", sends planning message → done, no file.
- Tries to use the `write` tool, hits escape issues, gives up with a planning message.
- Repeatedly says "I'll switch to a Python script via temp file" without ever doing it.
- Uses an approach (e.g. sets a module-global dict for idempotency) but never writes the file.

**Working subagents share a pattern:** they IMMEDIATELY use the `write` tool to create
the file with rough content, then iterate to fix errors. The failed ones plan first.

**Mitigation when spawning new subagents:**
Use a forceful, action-first prompt template like:

```
DO NOT respond with a text-only plan. In THIS turn, you MUST:
1. Use the read tool to read references
2. Use the write tool to create <output_path> with <N> pairs as JSONL
3. Use the pwsh tool to run the validator
4. Reply with the sha256

If escape issues arise: write a Python generator to a .py file in the project's
`meta/` folder (e.g. `meta/_gen.py`), run it with the venv, then delete the
generator. Do NOT just plan around the issue.
```

Also: the success rate for subagents writing >100 pairs in one shot is ~30%. Smaller
asks (30-50 pairs) have higher success.

## 5. The programmatic generators

A `gen_shape_b.py` was started this session but was deleted (had a JS-template-literal
escape bug that produced unterminated string literals). **The generators described in
this section are templates to write — none of them exist on disk yet.**

Recommended approach for writing them safely:

1. **Write the generator as plain Python, no JS templating.** Either:
   - Use a Python `with open() as f: f.write()` approach, where the generator builds
     each snippet via list-of-strings joined with `\n`, OR
   - Write the generator as a heredoc-style file with literal triple-quoted strings.

2. **Avoid nested f-strings.** If you need to embed dynamic values, use:
   `""" + var + """` instead of `f"""...{var}..."""` inside another template.

3. **Avoid single-line nested quotes.** When emitting Python code that itself has a
   triple-quoted docstring, prefer writing the output file as a sequence of lines
   rather than as one giant string.

### Minimal Shape B generator skeleton that works

```python
import json, random
from pathlib import Path

OUT = Path('minimax3/data/distillation_data/shape_b_completion/batches/batch_g001.jsonl')
OUT.parent.mkdir(parents=True, exist_ok=True)

def make_snippet(imports, func_def, body, demo):
    """Build a snippet as a list of lines, then join with newlines."""
    lines = [imports, '', func_def, body, '', 'if __name__ == "__main__":', demo, '']
    return '\n'.join(lines)

snippets = []

# Family 1: slugify (30 variations)
for name in ['slugify', 'to_slug', 'make_slug'] * 10:
    func = 'def ' + name + '(s: str) -> str:'
    body_lines = [
        '    """Convert a string to a URL-safe slug.\n\n'
        '    Examples:\n'
        '        >>> ' + name + '("Hello, World!")\n'
        '        \'hello-world\'\n'
        '    """',
        '    import re',
        '    s = s.lower().strip()',
        '    s = re.sub(r"[^a-z0-9\\s-]", "", s)',
        '    s = re.sub(r"[\\s_-]+", "-", s).strip("-")',
        '    return s',
    ]
    demo = '    print(' + name + '("Hello, World!"))'
    snippets.append(make_snippet(
        'import re',
        func,
        '\n'.join(body_lines),
        demo,
    ))

# Write
out_lines = [json.dumps({'text': s}, ensure_ascii=False) for s in snippets]
OUT.write_text('\n'.join(out_lines) + '\n', encoding='utf-8')
print(f'Wrote {len(out_lines)} snippets')
```

Run with: `& .\.venv\Scripts\python.exe meta\gen_shape_b.py`

## 16. 2026-09-07 — Fix tuple-wrap examples in Shape A new wave

`meta/gen_shape_a_bulk.py:_expand` now calls `_strip_outer_parens(ex)` before substituting `{EX}`. Strips a single outer paren-wrap when the example is a tuple like `"('a', 'b')"` or a 1-tuple like `"(123,)"`. Without this, the instruction template `"Example: \`{FN}({EX})\`"` produces `fn(('a', 'b'))` for multi-arg fns and `fn((123,))` for single-arg fns — both raise TypeError when followed as written.

### Applied fixes

1. **`_fix_a_examples.py`** — post-processor that walks `batch_g1000+` Shape A files, finds `Example: `fn((arg1, arg2, ...))`` patterns where the signature has 2+ args, and rewrites the instruction to `Example: \`fn(arg1, arg2, ...)\``. Used on the 12,976 existing new-wave pairs to fix 5,440 of them (the multi-arg cases). Single-arg 1-tuple cases like `(123,)` were left as-is (they're rare and harmless when runnable because the function actually receives the inner value).
2. **`gen_shape_a_bulk.py`** — template-side fix so future regenerations don't reintroduce the bug. Affects all current and future Shape A topics that go through `_expand`.
3. **`aggregate.py`** re-run: 0 dedup errors, all 4 shapes still pass. Stats unchanged: 26,469 pairs (est tokens: 2,093,953, down from 2,108,855 since the unwrapped instructions are shorter).

Remaining fails are decorator-style `cache_decorator(fn)` examples where the example passes a bare function reference that the test harness can't resolve — not a corpus bug.
